# Standing quality instructions (include verbatim in every runtime-code wave brief)

Eight standing lines that pre-empt the most common corrective wave. Governing rules live in `SKILL.md` `### Step 2: Per-wave loop` → **2a. Dispatch the-looper**. The fourth fires only on deletion/removal waves, the fifth only on doc/example waves, the seventh only when a wave discovers an already-shipped claim is false, the eighth only when a brief sends an agent to determine what an ambient condition or override value does.

- **The wave's own new comments default to ZERO, and the wave proves it before finishing.** `the-chronicler.md` `## What You Document` is the budget: a comment ships only for a WHY a reader would otherwise UNDO, a one-line landmine marker, a `@throws`, or an external-contract surface (Swagger, DTO fields, README, public API) where prose is the product and thin is the defect. One line is the ceiling everywhere else, declaration position included — a header essay is still an essay, and it is the offense that survives longest because it looks respectable. Two classes are banned outright and are what waves keep shipping: the **justifier**, prose defending code for being CORRECT (aria/a11y that works, focus that lands, errors that get caught, types that hold — correct is the baseline, not a story, and defending it reads as patronizing to whoever wrote the code), and the **user story**, a persona or scenario narrated into a source file. Observed: a nine-line alert component carrying a four-line header defending its own a11y, rationale blocks on three props, and an inline comment repeating the header — where the correct total was ONE line. Prose warnings alone have not stopped this, so the mandatory step is mechanical: before declaring the wave done, run `~/.claude/scripts/doc-bloat-scan.sh <every file the wave touched>` and account for every candidate it emits — cut it, or name which of the four earners it is. One kind answers to neither: an `unterminated-block` is a diagnostic about the SCAN, not a comment — a `/*` in code position that never closes, or a file the scanner's lexer handed back to line shapes. Answer it by checking the cited opener line, never by a cut. A wave that adds source files and adds no comments has PASSED this line, not skipped it.
- **Test any NEW cross-layer or dynamic invariant this wave introduces — in BOTH directions if it's a toggle.** Nested-tablist isolation, a predicate that flips an attribute on/off (a panel that gains `tabIndex` when empty and must _re-drop_ it when filled), any state-machine edge — tends to ship the forward assertion and omit the reverse/isolation one, which the chemist flags as a blocker. Name the invariant in the brief and require its round-trip test. Observed twice in one run, each costing a corrective wave + re-crew.
- **Where a file ALREADY has a top-of-file docstring, reconcile it too, not just inline comments, when the change invalidates a stated invariant.** A wave making a previously-unconditional behavior conditional (e.g. "panel is always `tabIndex={0}`" → "only when it holds no focusable descendant") reliably fixes the inline comment but leaves the overview docstring asserting the old invariant — now contradicting the file's own new comments; the chronicler flags this as doc-drift. Instruct the-looper to grep the file's header docstring for any claim the change falsifies. Reconcile means cut or correct — where the falsified claim was never earned in the first place, deleting it is the reconciliation, and a file with no header is not a gap to fill (see the zero-default line above).
- **On a DELETION / feature-removal wave, sweep the WHOLE repo for prose referencing the deleted symbol or feature — not just edited files.** A deletion's stale-reference blast radius reaches files it NEVER touches: consumer UI copy, a sibling empty-state panel's instructions, backend `@ApiResponse`/DTO descriptions, DB-schema comments, READMEs. Single costliest recurring corrective-wave cause on removal goals. Brief the-looper to `grep -ri` the deleted feature's name AND public symbols across the whole repo (both apps in a monorepo), reconcile every hit, then re-run the grep to prove none survive. Most dangerous class is **rendered user-facing copy**: a removal can leave an instruction promising a control that no longer exists (SC 3.3.2), shipping green because its test still asserts the stale string. Observed as an interim-crew BLOCKER — a deleted "try it out" form left a WelcomePanel telling users to "hit Send" on a gone form, plus ~15 other stale surfaces across both apps, costing a full doc-only corrective wave + full re-crew. See `[[feedback-deletion-blast-radius-doc-drift]]`.
- **On a wave that documents or hand-duplicates a trigger condition/config shape/API contract elsewhere (README, example configs, embedded YAML), verify the duplicate against the ACTUAL shipped code path, not just against what an earlier wave's commit message claimed.** A "docs-only" brief that just transcribes intended behavior can ship documentation that is internally consistent but wrong, because the thing it's describing changed underneath it and nobody traced the real trigger/branch logic. Observed: a prior wave taught a permission-gate module to recognize a new partial-approve trigger shape; the project's hand-maintained example workflow's `if:` pre-filter (a separate, intentionally-duplicated copy of part of that same trigger contract) still only matched the OLD shape, so the new trigger could never fire in practice — silently DOA. The interim crew pass on the logic-only diff never caught it, because the example file hadn't been touched yet and wasn't in that diff. It surfaced only because the docs wave's brief explicitly said "read the real code before writing the doc claim, and fix the duplicate if it's wrong" instead of "write the doc." Brief the-looper to trace the real branch/contract in the current code (not the commit message) for every hand-duplicated copy the wave touches, and treat a mismatch as an in-scope bug fix, not a separate finding to defer.
- **Grep for orchestration-internal references (wave numbers, "corrective wave," "prior-wave convention," a run's phase/round labels) in every file, test name, and checked-in fixture filename the wave touches, and confirm-empty before finishing — a warning alone does not prevent this.** A wave number means nothing to a repo history that outlives the run; it reads as jargon to any future maintainer or, worse, to the _next_ wave in the same run, which then cites "wave 2" as if it were a stable identifier. This is the single most-recurring corrective-wave cause once a run passes 3-4 waves: observed FOUR times on one branch (a code comment, a test name, a checked-in golden-fixture filename, and even a corrective wave's own commit body), despite each earlier fix being called out by name as "a recurring category" in every subsequent brief. Prose warnings alone did not stop the recurrence — what worked was a _mandatory verification step_: instruct the-looper to run `grep -in 'wave[0-9]\|wave [0-9]\|corrective[- ]\|prior[- ]wave'` (adjust the pattern to the run's own labeling) across every file it touched, immediately before declaring the wave done, and to treat a non-empty result as unfinished work, not a nit to defer. Scope the grep to files the wave touched, not the whole repo — a whole-repo sweep will also catch pre-existing, out-of-scope debris from earlier merged PRs, which is a different (and not this wave's) problem; don't let the wave "fix" debris it didn't create. A commit message or PR body that already published cannot be scrubbed after the fact — the guardrail is for the wave's _own_ commit, not a retroactive rebase of history.
- **On discovering an already-shipped FACTUAL CLAIM is false — not a dangling reference, not orphaned debris, a statement that was asserted true and turns out not to be — sweep every WORDING of it across the whole repo, not just the file where it was found.** This is a fourth kind of hand-back flag, distinct from all three `protocol-detail.md` `## Step 2b-flags` buckets (cross-file incompleteness, self-caused debris, out-of-scope observation): none of those fit "we already told people X and X is wrong." Routed as cross-file incompleteness it inherits a later wave's file scope and never reaches source comments, the CHANGELOG, emitted `.d.ts`, or the PR body — every surface that already carries a copy of the false claim. Grepping the exact sentence you just fixed is what makes the fifth copy invisible; a paraphrase, a shortened form, or a copy in a different tense all read as false hits to a literal grep and are exactly the copies most likely to survive. Sweep by WORDING (the claim's substance, checked by re-reading each hit — not a single fixed string) across every tracked file, not only the ones this wave already touched, and confirm none remain before declaring the wave done. Observed costing four corrections in four places on one run, three caught by review rather than by a sweep, the last gating on a string that ships to consumers through `dist/`.
- **On a brief that sends an agent to determine what an ambient condition, environment variable, or override value ACTUALLY does, name the specific axis to vary and require the full comparison table — never a single probe.** A single-ambient probe cannot distinguish two hypotheses that predict IDENTICAL output under the one condition tested, e.g. "the value pins X" vs. "the value clears the override, and X is only what this machine happens to report by default" — the clearing case is exactly the one that makes the result machine-dependent, and a probe run on one machine in one mode can't tell you which hypothesis is true. Brief the agent to run/compare BOTH sides of the axis explicitly (e.g. headless vs. interactive, this machine's default vs. another's) and report the full table, never a single verdict. Observed: two crew agents returned opposite verdicts on the same value from compatible data because one had launched headless-only and the other hadn't; the orchestrator burned a full re-probe to discover they had measured different things rather than actually disagreed. The briefing rule is the fix, not the re-probe — name the axis up front.
