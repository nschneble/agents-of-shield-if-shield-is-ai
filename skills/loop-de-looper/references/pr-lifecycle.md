# PR lifecycle, push ownership, and the terminal body refresh

Detail for `SKILL.md` `## Protocol` Step 2a (brief PR directives) and Step 4 (finalization). The SKILL states that a run ends with exactly one PR and that the loop never flips draft to ready; the mechanics are here.

## One branch, one PR, created early

A multi-wave run shares ONE branch and ONE PR. The PR is created ONCE, EARLY — not deferred to "the end." Deferring orphans it: each wave reasons "not my job, the orchestrator opens it at the end," and the termination step historically had no PR action, so no actor ever created it. The run shipped seven green commits and zero PRs.

1. **Wave 1**, after the first successful commit: the brief carries `pr: create-on-wave-1` + `target.push: true`. `looper-commit` pushes (`git push -u origin <branch>`) and creates the draft PR (its Step 3), assigned `@me`. A real PR # now exists.
2. **Waves 2…N**: the brief carries `pr: existing #N` + `target.push: true`. `looper-commit` Step 2 detects the open draft and commits into it; the push keeps the PR current per wave.
3. **Termination**: the finalization backstop below asserts the PR exists before goal-complete, and creates it if some earlier wave missed it.

`pr: skip` is the ONLY suppressor of PR creation, and it is explicit and rare. "Don't flip to ready-for-review" is NOT `pr: skip` — the draft is still created; only the draft→ready flip stays the user's call. Collapsing those two is the exact bug this section exists to prevent.

Push is the orchestrator's call BY DESIGN — so the orchestrator must actually make it. An orchestrated run that never pushes can never open a PR: `gh pr create` requires the branch on the remote. `target.push: true` on every wave is not optional in orchestrated mode.

## Step 4 — PR finalization backstop

Runs on every path before declaring goal-complete or surfacing the report.

1. Detect the run's PR: `gh pr list --head <branch> --state all --json number,url,state`. Persist `number`/`url`/`state` to `run-state.json`, and if `pr.body_sha` is unset, stamp it from the current body — the wave-1 executor writes that body inside its own dispatch, so the orchestrator stamps on first sight rather than expecting it in a hand-back.
2. No open/draft PR but committed work exists on the branch → ensure the branch is pushed, then create the draft now (`looper-commit` Step 3). **Exception: a CLOSED PR is not a missing one.** Step 1's `--state all` surfaces it, and closing a PR is a user act (item 4) — do NOT open a replacement, which would restate work the owner just dismissed. Surface the closed PR and stop.
3. Report the PR #, URL, and draft/ready state in the final state report. "Branch is not a PR" is not an acceptable terminal state for shipped work. Flipping draft → ready stays the user's call; creating the draft does not.
4. **A PR state the loop did NOT itself set is a USER edit — surface it, never revert it.** The loop's own components never flip draft→ready, so a PR found ready at finalization was not the loop: leave it, and do NOT `gh pr ready --undo`. Same for a closed PR. The comparison is against `run-state.json`'s `pr.state`, the value the loop last wrote — any mismatch is the owner's. Observed: a run found #105 flipped-to-ready and body-rewritten by the user, un-readied it AND overwrote the body. A genuine tool bug goes to the user to decide; the loop does not self-correct external state.

## Step 4 — structured-recap PR-body refresh

Refresh the PR body ONCE, at termination, after finalization and recap. `looper-commit`'s `## Structured recap (PR-body section)` defines the FORMAT (file-tree, collapsed `<details>` diff hunks, UI wireframe); this step decides WHEN it fires. The body was created early at wave 1 before the whole-run diff existed, so the rich recap lands as a terminal `gh pr edit <N> --body` refresh — an external-state edit that changes the PR, not the branch.

- **User-edit guard (check FIRST, before composing anything).** The body may have been edited by the USER since the loop wrote it at wave 1. The baseline is `run-state.json`'s `pr.body_sha` (`state-schemas.md`), stamped after every write the loop itself makes. Before refreshing: read the live body (`gh pr view <N> --json body --jq .body`), hash it, compare. Match → still the loop's own text, refresh normally. Differ, or `body_sha` absent → treat as user-edited. Do NOT replace it with a generated recap; two allowed moves only: (a) leave it entirely, or (b) AUGMENT it additively — append genuinely-new items into the sections the user already wrote, leaving every line they authored byte-identical, matching their structure. The distinction is augment vs overwrite, never touch vs don't-touch. Re-stamp `pr.body_sha` from whatever you end up writing.
- **Recovering a body an earlier refresh already clobbered.** The edit history is readable: `repository.pullRequest.userContentEdits(first:N){nodes{editedAt editor{login} diff}}`. Each node's `diff` is that revision's FULL body text, not a patch — GitHub's schema calls it "a summary of the changes," which is wrong. The connection is **newest-first**, so `nodes[0]` is the CURRENT body: on a clobbered PR that IS the clobber, and restoring it re-applies the damage. The user's text is the next node down. Walk outward from `nodes[1]` for the newest revision that isn't the loop's; `diff` is nullable on older or deleted revisions, so skip null nodes instead of reading one as an empty body. `editor.login` cannot discriminate — the loop authenticates as `@me`, so its edits carry the owner's login too; go by timeline position, never by author. Best-effort: if no node holds the user's version, say so in the report and leave the live body alone.
- **Source diff.** Build every block from the WHOLE-RUN diff — the SAME base the final crew derives (`git diff <wave1>^..HEAD`, `protocol-detail.md` `## Step 3`). Reuse it; do NOT reinvent a base.
- **UI-glob gate.** Reuse the EXISTING UI-glob detector (`protocol-detail.md` `## Step 2b`). Matched → INCLUDE the before/after wireframe + a11y call-out; no match → omit.
- **Small-diff skip.** Honor `looper-commit`'s small-diff skip — a genuinely tiny run gets NO refresh; the raw diff reviews faster.
- **Shape first, then brevity + voice.** Assemble the body per `looper-commit`'s PR-body guidelines — **read the target repo's PR template and fill ITS sections, in ITS order, before anything else** (`looper-commit` `## Step 3`, which also covers the `docs/` and root locations and the multi-template directory form), then lean sections, no diff restatement, no AI-attribution trailer — and run it through `the-ghostwriter` before the `gh pr edit`. The template rule is named here and not just cited because this is the path where the ORCHESTRATOR writes the body itself: `gh pr create`/`gh pr edit --body` never prefills a template, so a body composed outside a `looper-commit` dispatch reaches GitHub in whatever shape its author chose, and the maintainer rewrites it to house shape by hand. Observed on this repo's own PR #55. **On the augment path the ghostwriter sees only the lines you ADD** — the user's own prose ships byte-identical however it reads, since a voice pass over it is exactly the overwrite the guard forbids.
- **Best-effort, never a gate.** A failed refresh (API error, body too long) LOGS and continues to goal-complete; the backstop above owns the PR's existence, the recap only enriches it.
- **Skip on the STOP/escalation path** — same discipline as recap and run-level learn.
