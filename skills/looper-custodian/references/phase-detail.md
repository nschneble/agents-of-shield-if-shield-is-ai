# Per-phase detail — C, A, B

The sub-mechanisms each phase runs: what they read, what they write, and
the incident behind each rule. SKILL.md `## Maintenance run` carries the
phase order and each phase's routing decision; this file carries the
mechanics. Consult it when executing the phase it belongs to.

## Phase C

- **Backed by a cross-run history index** — `local/custodian/history-index.jsonl`, append-only, one record per `gates.jsonl` line across the repo list. Each record carries the gate's fields verbatim (`wave, kind, agent, verdict, outcome, verified_by, blockers, summary`) plus `repo`, `branch`, the branch's touched `files` (from `git log --name-only` for its commits; `[]` when git can't resolve them — never invented), and a `cite` = `<repo>/local/loops/<branch>/gates.jsonl:<line>`.
- **Incremental ingest, not re-scan.** Phase C runs `scripts/custodian-history.sh ingest`, appending ONLY `gates.jsonl` lines whose `cite` isn't already indexed (anti-join by `cite` in `jq`). Weekly cost is the _new_ runs since last week, not every run ever. Touched `files` come from commit SHAs named in each run's summaries (`git cat-file`-verified, then `git show --name-only`) — SHA-based so they resolve after the branch is merged + deleted. (The `ctx` pattern grafted onto our substrate: query one structured store rather than re-scan, JSONL + `jq`, no SQLite — `gates.jsonl` is already the structured log. `[[reference-ctx-agent-history-search]]`, `[[no-third-party-hosted-tool-reliance]]`.)
- **Guardrail replay (the Sefz graft).** Beyond the free-text digest, Phase C runs `scripts/custodian-guardrails.sh` — a deterministic replay of the loop's own "never/always" guardrails encoded as `jq` predicates over the same index, the way Sefz (arXiv 2605.13044) turns a natural-language guardrail into a reachability query over an annotated trace. Three today: **G1** no verdict without a run (`task_tool_available:false ⇒ ran:false ⇒ no verdict`, the loop-de-looper `## Gate artifacts` hard rule); **G2** the provenance lint reused **verbatim** from `skills/loop-de-looper/references/state-schemas.md` `## Provenance lint` (single source of truth — not re-encoded); **G3** no committed wave without a `verified_by=="executable"` gate line (issue #29's execution-evidence assertion). Read-only, index-backed, cited — each violation prints the record's verbatim `cite`; exit 1 on any violation. Lines from runs **predating the `verified_by`/`outcome` schema are EXEMPT** (reported separately, never violations). state-schemas.md's legacy note prescribes a _temporal, per-file_ exemption; because this replay runs over the era-mixed cross-repo index it uses a per-_line_ extension of that note — a record with no `verified_by` key is pre-schema. The ingest writer copies the key into a record only when the source line carried it, so that absence (and the exemption) survives `history --rebuild`; without it the replay would flood false positives on archived history. Violations are informational signal for the digest — a compliance finding a per-run learn can't see — on the same read-only/auto side of the propose-dispose line as the rest of C; not a checkbox unless one routes to a scoped fix. `[[no-third-party-hosted-tool-reliance]]`: mine Sefz's _pattern_ (trace-as-query), not a tool — pure `jq`, no store.
- **Derived + regenerable — while the source exists.** The index is a cache of `gates.jsonl`, so `history --rebuild` re-derives it from source; a corrupt or lost index is never a data-loss event. But rebuild-ability holds ONLY until Phase A reaps the source — which is exactly why C runs first and Phase A carries the ingest-guard. It's gitignored scratch, same status as `local/loops/`, and sits on the read-only/auto side of the propose-dispose line.

## Phase A

- Squash-merge caveat: if `gh` is unavailable, ancestry alone can't see a squash-merge, so a squash-merged-and-deleted branch reads as unmerged and is conservatively **kept** (never wrongly reaped). Log it as `kept (merge unverifiable — gh absent)` so the miss is visible, not silent.
- **Audit every KEPT dir's snapshot, and only the kept ones.** `REPO_ROOT=<repo> bash scripts/loop-state-audit.sh --dir <dir>` compares `run-state.json` against the append-only records beside it (`skills/loop-de-looper/references/state-schemas.md`). Kept is exactly the right set: those dirs own in-flight or resumable work, so a snapshot that has silently lost a wave's position is the one thing that makes the resume it exists for worse than useless. A reaped dir is merged and about to be deleted — auditing it buys nothing. `REPO_ROOT` must name the repo owning the dir, since the sha arm resolves against that checkout and declines rather than guessing when it cannot; running the sweep from this repo without setting it would audit every other repo's shas against the wrong history. Report-only, never repaired: `run-state.json` is regenerable scratch, but a snapshot quietly rewritten by an unattended cron is a position nobody chose, and the propose/dispose line puts that on the human side. Log one line per audited dir with its exit code.
- **Check every KEPT dir's executable claims against the runtime's receipts.** `bash scripts/loop-receipts.sh --dir <dir>` asks whether a wave that declared `verified_by: "executable"` has a receipt behind it that the executing agent did not write (`hooks/record-execution-receipt.sh`). Same kept set and same report-only status as the snapshot audit above, and the same reason: a resumable run is the one whose evidence still matters. A dir with no `receipts.jsonl` is **NOT EVALUABLE, never a violation** — receipts begin when the hook is installed and every archived run predates it, so treating absence as failure would flood exactly the false positives the legacy `verified_by` exemption exists to prevent. Do NOT pass `--strict` on the sweep for that reason. Log one line per audited dir with its exit code.

## Phase B

- **The fingerprint pre-filter is scoped to `file:line`-shaped citations only.** `scripts/custodian-fingerprint-cache.sh` caches one sha256 hash per `(memory_file, cited_abs_path)` pair at `local/custodian/fingerprint-cache.json` (gitignored local state, same shape as capn-hook's `.capn/map.json`). It cannot help symbol/flag/route citations that don't reduce to one backing file's content, or a citation whose surface is a whole directory — those always go to the LLM fan-out. `diff` is conservative by construction: a hash change can mean the cited line drifted OR that something unrelated elsewhere in the file changed, so it always over-triggers a re-check, never under-triggers into a false `UNCHANGED`. After each subagent confirms a citation still resolves (whether it arrived as `NEW`/`CHANGED` from the diff, or was hand-verified this run for some other reason), the orchestrator calls `record` to refresh that citation's cached hash for next run — `UNCHANGED` citations need no refresh, their cached hash already matches. `GONE` citations are NOT re-recorded and NOT removed from the cache while the `B-retire`/`B-repoint` proposal sits unresolved in the issue — next run's diff reports them `GONE` again, which is correct: nothing has been decided yet. A cache with no prior entry for a citation (first run after adopting this, or a citation new to Phase B) reports `NEW` and pays the full audit cost once, same as today.
- **Also enumerate every `memory: user` agent's own namespace, once per run, not once per repo.** Glob `~/.claude/agents/*.md` frontmatter for `memory: user` (e.g. `the-looper`); each match gets its `~/.claude/agent-memory/<agent-name>/` dir added to the SAME audit pass, with its own `files_total` counted separately from any repo's project memory (it's a single global namespace, not repo-scoped — auditing it once per repo would double-count and mis-cite). This exists because a `memory: user` agent's own writes default to this namespace, not project memory — see `[[the-looper.md's memory: user]]` / `looper-learn`'s "Save lessons at the right level" section — so a project-memory-only audit misses half the corpus.
- **If delegating the audit** to a subagent (e.g. a large dir like linklater's 60+ files), hand it the **explicit absolute path list** and grant it **Read + Grep, and nothing else** — never bash discovery. The subagent reports back per file so coverage is countable.
- **Why Grep, and how narrowly.** SKILL.md `### Phase B` resolves a citation "by existence-plus-`grep` for the symbol", and a Read-only agent cannot run that test: it confirms what it opens, so it catches "X moved to Y", but it can never establish "X names nothing anywhere". The asymmetry is measured, not argued. The 2026-08-31 run's log records "8 delegated Read-only subagents" and 20 proposals: 11 repoint, 3 distill, 2 merge, 2 migrate — 18 that repair, relocate, or consolidate — and only 2 that delete. Of those 2, one quotes the search behind it (`grep -rn UN_MIGRATED apps = 0 hits`); the other cites a rename rather than a search, which is the shape a retire is not allowed to rest on. So a Read-only fan-out reached one search-backed negative finding in 20. Separately, a later re-resolution of a 13-file namespace with Read + Grep surfaced 4 findings in the very namespace that run's shadow arm had read in full and proposed nothing for. So the grant is for **verification only**: searching the enumerated file set and the surface a citation names, for the symbol, flag, path, or route that citation asserts. **Enumeration stays orchestrator-owned and is still NEVER delegated** (SKILL.md `### Phase B`) — a subagent may not search the filesystem for memory files to audit, and a file absent from the list it was handed stays out of scope whatever a search turns up.
- **An unresolved citation is reported, never passed over.** When a citation can be neither confirmed nor refuted — no search available, a symbol too generic to settle, a cited surface unreachable from this run — report it `UNRESOLVED` against that file, quoting the citation and the search that failed to settle it. Same spirit as Phase A's `kept (merge unverifiable — gh absent)`: the miss is visible rather than silent. It never counts as resolved, and it is never grounds for a `B-retire`, which needs a relocation search that came up EMPTY, not one that could not run.
- **Count citations, not just files.** With the per-file read-back, each delegated subagent reports `citations_resolved` / `citations_total` for that file — a COUNT, never a per-citation list, which would bloat the return for no added falsifiability. `citations_total` is every `file:line`, script, symbol, flag, route, or path the file cites; `citations_resolved` is how many it put a search or an open behind. Both derive from the file in hand: an agent that cannot state them says so rather than estimating. The orchestrator sums them per namespace for SKILL.md's coverage verdict.
- **Skill-spec lint (propose-only signal).** Alongside the memory audit, Phase B runs `scripts/custodian-skill-lint.sh` over this repo's tracked `skills/` tree plus any root `CLAUDE.md`/`AGENTS.md`, porting the published Agent Skills spec lint schemas (agentskills.io/specification) into pure bash + awk + grep — no hosted tool (`[[no-third-party-hosted-tool-reliance]]`). Two tiers: **structural** findings (frontmatter allowlist + required fields, name pattern/length/dir-match, empty/over-length description, broken intra-skill links, a reference FILE nested deeper than one level, a false-positive-averse secret-leak scan) exit 1 and are surfaced as report signal — a concrete one may route to a `D-turncoat-<n>` proposal for a scoped fix; **advisory** findings (the ~100-token discovery / <5000-token body / <500-line / <150-line context-file budgets, token-counted approximately at chars/4, plus one reference file cross-linking another) are INFO-only, never violations, and inform **extraction** decisions (split a fat body into `references/`), never prose smoothing — the war-story prose is deliberate (`[[project-skill-slimming-yields]]`). Read-only and propose-only like the rest of the run: it never edits a skill, and description edits are explicitly out of scope (findings only). `scripts/custodian-skill-lint.test.sh` is its both-directions test.
