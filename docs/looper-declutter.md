# Looper Declutter — design rationale + decision log

The human dossier behind `skills/looper-declutter/SKILL.md`. The SKILL.md is the executable spec; this file records WHY the non-obvious choices were made, so a future edit doesn't re-litigate a settled call.

## Why it exists

Comment discipline was already fully owned — `the-chronicler` (mechanics), `the-ghostwriter` (voice/de-slop), `the-improver` (delete-restate) — but only enforced REACTIVELY, inside a `looper-review` crew pass over the pending diff. That covers new bloat a change introduces. It never reaches bloat that predates the change: a file whose comments were over-narrated long ago is never re-touched unless a diff happens to cross those lines.

`looper-declutter` is the proactive whole-repo sweep that closes the gap — exactly the relationship `looper-defend` has to `security-review`/`the-diamantaire`: they review the pending diff, defend hunts the whole repo. Declutter : comment-bloat :: defend : security.

The trigger for building it: a real target repo (Linklater) accumulated well over a thousand comment-bloat candidates the reactive crew had never seen.

## Governing principle: declutter PROPOSES, human DISPOSES

A comment is a judgment call, not a mechanical fact. An autonomous pass that auto-rewrote every flagged comment would flatten a deliberate GOTCHA, lowercase a proper noun, or truncate the one line that carries the real gotcha. So scan/triage/report run read-only and automatically; every snip is a checkbox that applies only after a human ticks it and runs `/looper-declutter apply`. There is NO auto-apply class — the one place this differs from defend, which auto-lands a dependency CVE bump. A dep bump has a mechanical oracle (suite stays green, diff confined to the lockfile); a comment trim has none, so it never skips the tick.

## Why these mechanisms (the non-obvious choices)

- **Reuse the owners; never duplicate them.** Four of the five requested rules (75-char wrap, lowercase `//`, WHY-only depth, the humanizer/de-slop) already live in `the-chronicler` and `the-ghostwriter`, which explicitly cross-reference each other to avoid a double pass. Declutter re-encoding any of them would fork the source of truth. So it contributes only two genuinely new things — a mechanical detector and the routing orchestration — and applies the owners' rules by reference. If an owner's rule changes, declutter inherits it for free.
- **The detector is self-contained.** `scripts/doc-bloat-scan.sh` is pure bash + awk + grep, no third-party linter, no tokenizer, no hosted tool (`[[no-third-party-hosted-tool-reliance]]`) — the same discipline as `scripts/custodian-skill-lint.sh`. It emits JSONL candidates and never edits or gates.
- **Full-line comments only, C-style only (v1).** The detector treats a line as a comment only when the trimmed line STARTS with `//`, `/*`, or JSX's braced `{/*`. That deliberately ignores trailing end-of-line comments and `#`-comment languages — and in exchange, a `//` inside a string or a `https://` URL is never mis-read as a comment. Recall precision beats recall breadth for a propose-only finder; the human-disposes gate is where the rest is caught. Extending to trailing comments and `#`-languages is future scope.
- **Snips group one wave per file.** All of a file's ticked snips are one cohesive, behavior-preserving doc wave, not one wave per comment — cheaper and more reviewable.
- **Comment-only, verified.** A snip edits comment text only; `looper-verify` confirms no non-comment byte moved and the suite stays green, else revert. This is the invariant that lets an autonomous trim be safe.
- **Repo-scoped, not cross-repo.** Declutter hunts the repo it is run in, like defend. Cross-repo reach is `looper-custodian`'s explicit-list domain; folding declutter into it is deferred, not designed out.

## Decision log

- **2026-07-30 — new skill vs. fold into existing surfaces.** Chose a standalone `looper-defend`-style skill over wiring the detector into `looper-custodian` Phase B + a `looper-review` enhancement. Rationale: the whole-repo, on-demand, `apply`/`--dry-run` shape is exactly defend's, and it gives a bloated repo a first-class entry point the reactive crew can't offer. A custodian Phase-B hook to schedule declutter across the repo list stays open as future scope.
- **2026-07-30 — no auto-apply class.** Considered mirroring defend's narrow auto-apply (dep-bump) for the most mechanical kind (`capitalized-slash`, `over-75`). Rejected: even lowercasing a first word can corrupt a proper noun, and truncation can drop meaning. Every snip needs a tick.
- **2026-07-30 — 75 chars, break at column 76.** The spec's "76 chars" is the cursor position at the wrap, i.e. 75 chars of content. This already matches `the-chronicler.md`'s 75-char hard limit; the detector's `over-75` kind and the global CLAUDE.md rule express the same number. No conflicting constant introduced.
- **2026-07-30 — dedupe by comment, not by kind.** One comment can trip several detector kinds; triage groups them into a single `D-<n>` so a reviewer sees one proposal per comment, not four.
- **2026-07-31 — aggressive triage: enforce, don't soften.** The first Linklater run reported "no bloated comments — kept all the WHY," the exact failure the skill was built to prevent. Root cause: triage carved out a "non-obvious WHY that runs long survives" keep, softening a rule the-chronicler already states with no exceptions ("single-line WHY only, no multi-line comment blocks mid-execution"). The carve-out is gone. Only two things survive: top-of-file/symbol headers and genuine one-liners. Everything mid-execution and multi-line is a snip whose default verb is delete — explicitly including comments that explain a framework primitive the author knows (`group`) or re-narrate the author's own named design (`border-shadow`).
- **2026-07-31 — survivor axis is POSITION, not the-chronicler's per-field letter.** Crew review (the-stickler) caught the rewrite claiming the-chronicler "blesses" a multi-line doc block before a prop — but `the-chronicler.md` `## Props` explicitly forbids a multi-line block per field. The reference "good" file (Linklater `LinkCard/index.tsx`) nonetheless keeps a multi-line `animationDelay` prop block, which the user blessed. Resolved on the user's operative distinction: what survives is a doc block in DECLARATION position (file top / before a symbol), pushed UP out of execution — not mid-execution. `jsdoc-block` is keep-LEANING, not a blanket pass: a per-field block on a self-evident prop or one echoing the type is still a snip (`## Do NOT document`). The "glosses a design-token/color that IS the answer" case routes to the-chronicler's Do-NOT-document list (its `:41` is almost verbatim the user's "don't explain why colors are colors"), not the-improver.
- **2026-07-31 — closer-count made honest (crew review, the-diamantaire).** The block finder stripped a leading `*` before the closer, so a bare `*/` reduced to `/` and was miscounted as a body line — the emit threshold was effectively "≥1 interior line" while the code and docs claimed ">1 body line," and the passing header count rode that accident. Fixed to strip the closer first (a bare `*/` → empty, uncounted) and test `block_body >= 1` explicitly, which preserves the exact emit set (an empty `/**` block now correctly drops) while making the rule — any multi-line block, opener + ≥1 content line + closer — true to the code. Do not "clean up" the strip order back.
- **2026-07-31 — detector blind spot: free-form `/* */` blocks were invisible.** The block finder only counted `*`-prefixed continuation lines, so a `/* … */` essay whose body lines are plain prose (the worst real offender) produced no `block-overexplained` candidate — it leaked only as loose `over-75` hits on whichever lines happened to exceed 75 chars, and a short-lined essay vanished entirely. Now ANY non-blank body line counts. Opener style splits the two cases: `/**` → `jsdoc-block` (a doc header, kept by default), bare `/*` → `block-overexplained` (the quarry). The block candidate carries its opener + first line as `text`, so the report shows what the block says instead of the old literal "block comment".
- **2026-08-08 — detector blind spot: JSX braced comments were invisible.** `.tsx`/`.jsx` were always in the extension list, so those files were walked and scanned, but the finder tested the trimmed line for `/*` and a braced comment starts with `{`. Every `{/* … */}` in children position therefore scanned as code, and a JSX tree could report zero comments while being full of them. `{/*` and `{/**` now open the same blocks (`*/}` closes them, which the closer already tolerated), with the same `block-overexplained` vs `jsdoc-block` split. The brace must abut the slash: `{ /*` is an object literal or an open block, not a comment.
- **2026-08-08 — a one-line `{/* … */}` is length-checked, not case-checked.** The deliberate call on the single-line braced form: it reaches `over-75`, but there is no `capitalized-slash`-style case check for it. That matches its unbraced twin `/* … */`, which has never been case-checked either. the-chronicler's rule ("Single-line: NO capitalize first word") arguably reaches any one-line comment, not just `//`, but honoring that would change the candidate set in every C-style file rather than just JSX, so it is its own decision and not a rider on a blind-spot fix. Braced-only was the worse option: two spellings of one token judged differently. Consequence to accept: a short `{/* This is a comment */}` produces no candidate.
- **2026-08-08 — the fixtures were stale, not the code.** The suite had been red since the 2026-07-31 free-form-block fix, whose semantics change (`block_stars > 1` to `block_body >= 1`, plus the `jsdoc-block` split) never reached `scripts/doc-bloat-scan.test.sh`: the RED fixture's only block was a `/**`, so `block-overexplained` could not fire, and the green fixture's one-star `/**` block became a legitimate `jsdoc-block` candidate. Both fixtures were corrected to the shipped rule. Do not "restore" a multi-line block to the green fixture.
- **2026-08-08 — a block candidate now quotes the line it cites.** The finder emitted the OPENER's line number with the FIRST BODY LINE's text, so prose sitting on the opener line was silently discarded and the report showed a quote that is not on the line it points at. That is misleading evidence in a tick-to-apply surface, where the quote is what the human ticks against. The emitted `text` is now the opener line verbatim when it carries prose, and `<opener> ... <first body line>` when the opener is bare — the elision mark says the words are borrowed from the next line. Measured over Linklater: 21 of 1078 block candidates (1.9%) sit on an opener carrying prose that was being dropped, and 12 of the 25 braced ones (48%), because a bare `{/*` on its own line is not idiomatic JSX the way a bare `/**` is idiomatic JSDoc. The emit set is unchanged; only the quote is.
- **2026-08-08 — braced doc blocks are never keep-leaning.** Three sites in the contract disagreed about whether `{/**` exists and what it routes to. A `{/**` parses only in JSX children position, so it is mid-execution by construction and the keep-leaning default — which is grounded in DECLARATION position — can never apply to it. `SKILL.md`'s scan bullet, survivor list, and routing table now all say so: unbraced `/**` stays keep-leaning, braced always routes to `block-overexplained`.
- **2026-08-08 — known hole, deliberately left open: an unterminated `{/*` blinds the finder to EOF.** A false or genuinely unclosed opener leaves the block state set for the rest of the file, so every later block, `stacked-slashes`, and `capitalized-slash` candidate is suppressed (`over-75` still fires inside a block), the unterminated block itself never emits, and the scan exits 0 with no signal. The braced spelling makes it more reachable. Not fixed alongside the quote fix: closing it changes the candidate set in its own right and deserves its own decision.
